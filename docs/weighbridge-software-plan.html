02 · Where to run it

Run it in-house now. Add a small cloud server later if you want to check from anywhere.

  • Weighing must run on the site PC in every option. The indicator is wired to that PC by an RS-232 cable, and weighing can't stop just because the internet does. A cloud-only setup would stop every truck during every outage.
  • Stage 1: in-house, ₹0 a month. The app, database and backups all live on the weighbridge PC. The owner checks it from a phone through Tailscale, a private link with its own two-step sign-in. Nothing is opened to the internet.
  • Stage 2: hybrid, about ₹1.5–4k a month. A small server in an Indian cloud region receives a copy of every ticket from the site. The owner and accountant can then open reports and bills from any browser, even when the site PC is off. This needs new code (Phase 3, about 2–3 weeks).

Logging in

  1. Type your username and password.
  2. If two-step login is on (always for the owner), open the authenticator app on your phone and type the 6-digit code.
  3. First time only: set your own password (at least 12 characters).
  4. You land on your page: Weigh for operators, Billing for accounts, Reports for the owner.

When something goes wrong

  • Forgot password: the owner resets it on the Users page. You set a new one at next login.
  • Lost phone: the owner presses "Reset 2-step" for you, then you scan a new code.
  • "Locked for a few minutes": 5 wrong passwords. Wait 15 minutes or ask the owner to re-enable you.
  • Owner locked out: on the PC run python -m weighbridge add-user to create a new admin, then fix the old account.

How the pieces connect

The weighbridge PC sits on two separate networks. Its main port joins the office network and the internet. A second, cheap USB network adapter (about ₹1–1.5k) joins a small PoE switch that only the cameras, RFID reader and relay module are on. That device network has no router, so the cameras can't reach the internet and nobody outside can reach them. Today only the indicator and printer are connected; the rest arrives with Phase 4.

04 · Flows

All the flows, step by step

Each diagram shows the normal path left to right. Red boxes are where the software refuses and why. Amber boxes are side paths or checks. The numbers (3 seconds, ±10 kg, 7 days, 5%) are the defaults in config.toml and can be changed.

Two-weighment ticket in the software now

The normal trip. A vehicle's second visit to the platform automatically closes its open ticket. The weight is always read from the indicator at the moment of capture.

One weighment with stored tare in the software now

For trucks weighed empty in the last 7 days. The operator picks the one-pass option; net is gross minus the stored tare, and the ticket is marked STORED_TARE.

Weekly tare refresh in the software now

Keeps stored tares honest. Tares are also learned automatically at every normal second weighment, unless they differ more than 5% from usual (then flagged and not learned).

Indicator fails: supervisor enters weight in the software now

Operators can never type a weight. A supervisor can, with a reason, and the ticket carries a permanent MANUAL flag that shows on the owner's reports.

Correct or cancel a ticket in the software now

Weights of a closed ticket can never change, not even by editing the database. Only party and material can be corrected, or the whole ticket cancelled, each with a reason.

Login in the software now

Personal accounts only. Office sessions end after 30 minutes idle; every session ends after 12 hours. Owner/admin accounts must use two-step login.

Month-end billing to Tally in the software now

Customers get a tax invoice (Sales voucher); contractors get a work statement (Purchase voucher). CGST + SGST when the party's GSTIN starts with 27, otherwise IGST.

Messages: WhatsApp, SMS, email in the software now

Messages never hold up weighing. They go into an outbox on the PC and a background job sends them.

Daily jobs in the software now

Run by the app itself while it is open. Keep the app running (auto-start with Windows) so these happen every day.

Internet outage in the software now

Everything that matters runs on the PC. Only remote viewing and outgoing messages wait for the internet.

Site to cloud sync Stage 2 · needs new code

Stage 2 only. Needs new code (Phase 3). The site PC pushes each closed ticket out to the cloud; nothing on the internet can connect into the site.

06 · Cameras and RFID

Phase 4a and 4b: truck photos, RFID and number-plate check, with lights and a hooter

No boom barrier. The traffic lights and hooter tell the driver when to drive on and when to leave, and the operator stays in charge of the capture. Both phases need new code, which I build once you've picked the cameras and reader, testing against simulators first.

4a · Photos about 1 week to build

  • At every capture the PC takes a photo from each camera and stores it with the ticket, with a fingerprint so it can't be replaced later.
  • The photo appears on the ticket page, the printed ticket and the WhatsApp image.
  • The top camera is the evidence against someone standing on the platform or a wheel off the edge.
  • If a camera is offline, the ticket is still saved and marked "no photo".

4b · RFID + plate check 2–3 weeks + 1 week on site

  • A tag on the windscreen is read as the truck approaches, and the plate camera reads the number.
  • Both must match the same vehicle in the Vehicles master. Then the vehicle number fills in by itself and the light turns green.
  • After capture, a short hooter and the light returning to red tell the driver to leave.
  • A mismatch or unknown tag keeps the light red, sounds a long hooter and needs a supervisor. A truck without a tag can still be weighed by typing the plate; its ticket is marked.

4a · Photos with every weighment Phase 4 · needs new code

Photos are taken by the server at the moment of capture, never uploaded by hand, and stored with a fingerprint so a photo can't be swapped later.

4b · RFID + number-plate check, lights and hooter (no boom) Phase 4 · needs new code

The tag and the plate must both point to the same vehicle before the light turns green. With no boom barrier, the lights and hooter tell the driver what to do.

Where to mount things

  • Plate cameras: 3–5 m high, 15–30° down towards the plate, 5–10 m before where the front wheels stop. One faces trucks coming in, one faces the other end.
  • Top camera: on a pole or the control-room wall, seeing the whole deck.
  • RFID antennas: 3–4 m from the lane at windscreen height, one per approach.
  • Lights: one per approach, where the driver sees them from the cab. Hooter near the control room.

What each device must support

  • Cameras: ONVIF and a snapshot URL, RTSP, fixed IP, local admin password. For ANPR: sends plate results by HTTP to the PC, or can be asked for them.
  • RFID reader: LLRP over the network (port 5084). Avoid readers that only work with their own Windows software.
  • Relay module: Modbus TCP (port 502), relays rated for the contactor coils.
  • Before buying, send me the model numbers and I'll confirm they'll work.

08 · Integrations

What each integration needs

Each one is switched on in config.toml and takes effect after restarting the app. Start with the indicator and printer. The others can go live one at a time as their approvals come through.

Weight indicator ready

You need
The indicator's serial (DB9) port set to continuous output; a USB-to-serial adapter; a DB9 cable (try straight first, then null-modem). If the output setting is under the Legal Metrology seal, ask the maker's engineer to set it.
Steps
  1. Connect; note the COM number in Device Manager → Ports.
  2. With a load on the platform, run python -m weighbridge sniff --port COM3. It tries 9600, 4800, 2400, 19200 and 1200 baud and prints the weights it finds.
  3. Set [indicator] source = "serial", port, baudrate, and multiplier = 1000 if it sends tonnes.
  4. From the stamping certificate: capacity_kg = Max, stable_tolerance_kg = scale interval (e).
Test
Compare the screen with the indicator display for five trucks. Pull the cable: within a few seconds the screen must show "No signal" and refuse to capture.
Common problems
Nothing received → wrong COM port, cable pins, or output not set to continuous. Wrong numbers → send me the raw line from sniff and I'll write the exact pattern.
Cost / time
₹1–2k · half a day

WhatsApp: ticket image to party and truck owner ready

You need
  1. A Meta Business account (business.facebook.com), verified with GST or Udyam certificate and business address.
  2. A phone number for the business that is not already on the WhatsApp app (a new SIM or landline that can receive an OTP call).
  3. In WhatsApp Manager: add the number, get its Phone number ID, and get the display name approved.
  4. A System User with WhatsApp messaging permission and a permanent access token.
  5. A message template named weighbridge_ticket, category Utility, language English, with an image header and body text with 3 variables, e.g. "Weighment ticket {{1}} for vehicle {{2}}: net {{3}} MT."
  6. A payment method in Meta Business settings.
config.toml
[whatsapp] enabled = true, phone_number_id, access_token, mode = "template", template_name, template_language. On each party fill in WhatsApp; on each vehicle the owner's WhatsApp.
Why a template
Meta only allows businesses to message someone freely within 24 hours of that person writing to you. Tickets go to people who haven't written, so an approved template is required.
Cost / time
Utility messages cost roughly ₹0.1–0.2 each in India (check Meta's current rate card). Verification takes 2–10 days; template approval minutes to 2 days. New numbers start with a low daily limit that rises with verification and good quality.
Easier route
A WhatsApp provider (AiSensy, Interakt, Gupshup) handles sign-up for about ₹1–3k a month. That needs a small code change to use their API. Ask me if you go this way.
Test
Add your own number to a test party, close a ticket, and check the System page outbox shows "sent".

09 · Security

Security in each setup

Already in the software

  • One login per person, five roles, owner-only user management.
  • Two-step login (authenticator app), compulsory for the owner/admin role.
  • Lockout for 15 minutes after 5 wrong passwords. Passwords stored as scrypt hashes.
  • Office sessions end after 30 minutes idle, all sessions after 12 hours.
  • Protection against forged form submissions (CSRF) and strict browser security headers.
  • No weight can be typed except by a supervisor with a reason. The ticket is flagged.
  • Weights of closed tickets, and the audit log, are locked in the database itself.
  • A hash-chained audit log that reports any tampering. The chain code goes out in the daily email.
  • Excel downloads can't carry spreadsheet formulas typed into the app.

What you add per setup

  • Stage 1: BitLocker on; Windows login password with no auto-login; config.toml readable only by the app's Windows account; Windows Update on; no remote-desktop tools left running; backups leaving the PC.
  • Office PCs on the LAN Phase 2: I add HTTPS first, then set server.host to the PC's address and allow only office PCs in Windows Firewall.
  • Stage 2 cloud: HTTPS only, two-step login for every cloud user, firewall allowing only 443, automatic updates, encrypted backups with object lock, and a CERT-In empanelled security test before go-live.
  • Personal data (DPDP Act 2023): drivers' names and numbers are personal data. Put a notice at the gate, use them only for tickets and billing, and don't share exports outside the business.
